# Интеграция с Nano Banana (MCP)

На Шаге 4 Кеша **не только пишет промпты, а сразу генерирует картинки** через MCP-сервер Nano Banana.

## Какой MCP подключён
`@ycse/nanobanana-mcp` (запинен на версии 1.1.1). Работает с двумя моделями Google:

| Имя в `set_model` | Реальная модель | Маркетинговое имя |
|-------------------|----------------|-------------------|
| `flash` (по умолчанию) | `gemini-3.1-flash-image-preview` | **Nano Banana 2** |
| `pro` | `gemini-3-pro-image-preview` | **Nano Banana Pro** (релиз ноябрь 2025) |

**Nano Banana 2 (Flash) — основная рабочая модель.** Подходит для всего: рекламные креативы, текст в кадре (надписи, логотипы), лента, медийка. Быстрая, недорогая, качество достаточное для production.

**Nano Banana Pro** включается **только по явному запросу пользователя**. Дополнительно умеет:
- Разрешение до 4K (для печати, наружки, очень больших экранов)
- Доступ к Google Search для фактологии в визуале
- Чуть стабильнее со сложными многослойными композициями

Старая Nano Banana 1 (Gemini 2.5 Flash Image) в этом MCP не поддерживается.

## Доступные инструменты

| Tool | Что делает | Когда вызывать |
|------|-----------|---------------|
| `mcp__nanobanana__gemini_generate_image` | Сгенерировать картинку по промпту | Основной — на Шаге 4 для каждого объявления |
| `mcp__nanobanana__gemini_edit_image` | Отредактировать существующую | Если пользователь просит правку на конкретное изображение |
| `mcp__nanobanana__set_aspect_ratio` | Сменить соотношение сторон | Перед генерацией: 1:1 / 4:5 / 16:9 / 9:16 |
| `mcp__nanobanana__set_model` | Переключить Flash ↔ Pro | По умолчанию Flash. Pro — если нужно качество выше |
| `mcp__nanobanana__get_image_history` | Список ранее сгенерированных | Если пользователь хочет вернуться к предыдущей |
| `mcp__nanobanana__clear_conversation` | Сбросить контекст | Между разными продуктами |
| `mcp__nanobanana__gemini_chat` | Текстовый чат с Gemini | Не используем — есть Claude |

## Алгоритм Шага 4

### 4.1 — Стиль
Кеша предлагает 3-5 визуальных стилей (см. `visual-rules.md`), пользователь выбирает.

### 4.2 — Соотношение сторон
Спрашивает у пользователя:
> «Под какой формат генерим? Если оба — сделаем по два варианта на каждое объявление.
> 1. **Квадрат 1:1** — универсально для VK и Директ РСЯ
> 2. **Вертикаль 4:5** — мобильная лента VK
> 3. **Широкоформат 16:9** — Директ медийка, десктоп
> 4. **Сторис 9:16** — VK Stories
> 5. Несколько (укажи каких)»

Перед генерацией вызывает `set_aspect_ratio` с выбранным.

### 4.3 — Промпты
Пишет уникальные промпты для каждого объявления по шаблону из `visual-rules.md`. Перед генерацией показывает список промптов пользователю — даёт возможность поправить.

### 4.4 — Генерация
Для каждого объявления вызывает `gemini_generate_image` с промптом. Файлы падают в `~/Documents/nanobanana_generated/` с timestamp.

**Параллельность.** Если объявлений 5+, Кеша запускает генерацию **батчами по 3** (чтобы не упереться в rate limit). Между батчами короткая пауза.

**`use_image_history` — когда включать, когда нет.**
- `true` — **только** если хотим продолжить ту же сцену / тех же героев / то же помещение (например, серия из 3 кадров одной истории).
- `false` (по умолчанию для рекламных серий) — если хотим серию креативов в **одном визуальном языке**, но с **разными сюжетами, локациями, героями**. История держит сцену и героев, не стиль. Стиль удержится **текстовым стилевым блоком** (см. `visual-rules.md`, раздел «Стилистическая преемственность серии»).

Типичная ошибка — включить `use_image_history=true` плюс зашить в стилевой блок конкретные декорации (open-space, MacBook, plants). Получите 5 кадров одной локации с одним героем вместо серии. Если задача — рекламная кампания с разными ракурсами на одну концепцию, **выключайте** историю и держите вариативность через сюжет.

**Выбор модели.**
- **Flash (Nano Banana 2)** — основная модель для **всех** креативов по умолчанию. Закрывает 95% задач: рекламные баннеры, текст в кадре, любые форматы.
- **Pro (Nano Banana Pro)** Кеша **сам не предлагает** и не переключается на неё автоматически. Включается через `set_model({model: "pro"})` **только если пользователь явно попросил**: «давай на Pro», «нужно качество выше», «нужно 4K», «для печати/наружки».
- Перед переключением Кеша подтверждает: «Pro идёт медленнее и дороже примерно в 10 раз. Точно надо? Переключаю.»
- После выполнения задачи на Pro — возвращается на Flash (`set_model({model: "flash"})`), чтобы случайно не оставить Pro для следующей сессии.

### 4.5 — Показ результата
После генерации Кеша выводит список:

```
Объявление №1 → ~/Documents/nanobanana_generated/{filename}.png
Объявление №2 → ~/Documents/nanobanana_generated/{filename}.png
...
```

Кратко комментирует каждую картинку (1 строка): что видно, попало ли в концепцию.

### 4.6 — Правки
Если пользователь просит переделать конкретное изображение:
- Если правка по композиции/стилю → `gemini_edit_image` с указанием на старое изображение
- Если правка по сюжету → новый `gemini_generate_image` с переписанным промптом

Кеша **не предлагает** перегенерировать всё — только то, что просили.

## Если MCP не отвечает

Кеша **проверяет MCP в начале Шага 4**, до выписывания промптов. Если не работает — выполняет команду:
```bash
claude mcp list
```
И сообщает пользователю:
> «MCP Nano Banana не отвечает. Могу:
> 1. Переподключить (но потеряем сессию генератора)
> 2. Просто выписать промпты текстом, как раньше — и ты сам прогонишь их через AI Studio
>
> Что выбираешь?»

## Лимиты и стоимость

- **Flash** — быстрая, дешёвая. ~$0.0025 за изображение по тарифам Gemini.
- **Pro** — качественнее, дороже. ~$0.025 за изображение.
- Без бюджетных лимитов на ключе — может улететь. Кеша **напоминает** при первой большой генерации (10+ картинок): «Это ~25 центов на Flash или $2.50 на Pro. Норм?»

## Безопасность

API-ключ хранится в `~/.claude.json` как ENV-переменная MCP-сервера. **Не упоминается** в выводах Кеши. Не копируется в Excel/Sheets.
