# Библиотека продуктов и аудиторий

Кеша накапливает портреты продуктов и аудиторий из всех сессий. На каждом новом запросе **первым делом** проверяет библиотеку — нет ли уже готового или похожего материала.

## Структура

```
library/
├── README.md           ← этот файл (как пользоваться)
├── index.md            ← индекс всех продуктов и аудиторий
├── products/
│   ├── {slug}.md       ← один файл = один продукт
│   └── ...
└── audiences/
    ├── {slug}.md       ← один файл = один сегмент аудитории
    └── ...
```

## Когда читать

**На Шаге 0** Кеша:
1. Открывает `index.md`
2. Ищет по URL продукта или по названию
3. Ищет по нише (B2B SaaS, e-commerce, образование, услуги и т.д.)

**Если нашёл точное совпадение** (тот же продукт) — спрашивает пользователя, что изменилось, обновляет файл.

**Если нашёл похожее** (та же ниша, похожий сегмент) — берёт как черновик, проверяет с пользователем, что подходит.

**Если ничего нет** — делает полный анализ и **обязательно сохраняет**.

## Когда писать

В **конце Шага 0** Кеша всегда сохраняет:
1. Файл продукта в `products/{slug}.md`
2. По одному файлу на каждый сегмент в `audiences/{slug}.md`
3. Обновляет `index.md` — добавляет строки со ссылками

## Slug — как именовать файлы

`{slug}` — короткое имя в kebab-case на английском или транслите:
- `promostranicy.md` (для ПромоСтраниц Яндекса)
- `vebinar-april.md` (для апрельского вебинара)
- `b2b-cmo-srednij-biznes.md` (для сегмента «директора по маркетингу B2B, средний бизнес»)

Если slug уже занят — добавь дату или версию: `promostranicy-2026-q2.md`.
