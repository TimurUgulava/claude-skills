# Приём входа: текст, URL, файл

Задача шага — получить чистый текст статьи, сохранив все проверяемые детали (числа, даты,
имена, места, цитаты) и убрав шум.

## Определение формата

| Сигнал во вводе | Формат | Действие |
|-----------------|--------|----------|
| Пользователь вставил абзацы текста | Текст | Берём как есть |
| Строка вида `http(s)://…` | URL | Загрузка через WebFetch |
| Путь к `.docx` / `.pdf` / `.md` / `.txt` | Файл | Чтение через Read |
| И текст, и ссылка одновременно | Неоднозначно | Уточни, что проверять |

## Текст

- Отдели **проверяемую статью** от инструкций пользователя. Фразы «проверь вот это», «вот
  статья» — не часть материала, в декомпозицию не идут.
- Сохрани исходный порядок и все цифры/имена без «нормализующего» пересказа.

## URL

1. Загрузи страницу через WebFetch.
2. Извлеки основной текст статьи, отсекая навигацию, рекламу, комментарии, «читайте также».
3. Пейволл, 404 или пустой ответ — сообщи пользователю, что материал недоступен, и предложи
   вставить текст вручную. Не выдумывай содержание по заголовку.
4. Ссылку-источник самой статьи сохрани — она может понадобиться как справочный контекст (но
   не как независимый источник для проверки её же фактов).

## Файл

- **`.md`, `.txt`** — Read напрямую.
- **`.pdf`** — Read поддерживает PDF (параметр `pages` для больших файлов). Извлеки текст,
  проверь, что таблицы и числа считались корректно.
- **`.docx`** — попробуй Read; если содержимое не извлекается читаемо, сообщи об этом и
  попроси текст или конвертацию в pdf/md. Не гадай о содержимом.

## Нормализация перед декомпозицией

- Убери разметку и артефакты вёрстки, но **не трогай факты**: числа, единицы, даты, проценты,
  имена собственные, географию, цитаты остаются дословными.
- Сохрани порядок следования — он определяет порядок строк в таблице.
- Слишком длинный материал не сокращай самовольно: если объём велик, предупреди пользователя
  и предложи проверить по частям, чтобы ни одно утверждение не выпало.
