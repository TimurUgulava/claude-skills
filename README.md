# Claude Skills

Коллекция кастомных скиллов для [Claude Code](https://docs.anthropic.com/en/docs/claude-code).

## Skill Architect

**Архитектор скиллов** — проектирует и собирает промышленные скиллы для Claude Code по 4-фазному протоколу.

### Что делает

Берёт техническое задание (или просто описание задачи словами) и превращает его в готовый скилл: директория с `SKILL.md`, набор `references/` и упакованный `.skill` файл.

### 4 фазы работы

| Фаза | Что происходит |
|------|---------------|
| **Discovery** | Выясняет задачу, триггеры, формат вывода. Задаёт уточняющие вопросы |
| **Blueprint** | Выбирает архитектурный паттерн, рисует Mermaid-схему, предлагает структуру |
| **Compilation** | Собирает SKILL.md + references, упаковывает в `.skill` |
| **Debug** | Если что-то работает не так — предлагает протестировать и докручивает |

### Принципы

- **Атомарная детализация** — каждое требование декомпозируется на проверяемые инструкции
- **SKILL.md ≤ 100 строк** — ядро в body, детали в references. Экономит токены при каждом триггере
- **Архитектор, не исполнитель** — создаёт скилл для задачи, а не выполняет задачу сам
- **Генерализация** — скилл должен работать тысячи раз, не только на примерах из ТЗ

### Установка

Скопируйте директорию `skill-architect/` в ваш проект:

```bash
cp -r skill-architect/ /path/to/your/project/.claude/skills/skill-architect/
```

Или установите из `.skill` файла (если поддерживается вашей версией Claude Code).

### Как использовать

Скажите Claude Code что-то вроде:

- «Создай скилл для анализа PR»
- «Мне нужен скилл, который генерирует отчёты»
- «Спроектируй скилл для code review»

Skill Architect сам проведёт вас через все фазы.

### Структура

```
skill-architect/
├── SKILL.md                              # Ядро скилла
├── references/
│   ├── protocol.md                       # Фазы Discovery и Blueprint
│   ├── compilation-guide.md              # Правила сборки SKILL.md
│   ├── packaging.md                      # Упаковка в .skill
│   ├── debug-guide.md                    # Матрица диагностики
│   ├── patterns.md                       # Архитектурные паттерны
│   ├── skill-template.md                 # Шаблоны SKILL.md
│   └── eval-guide.md                     # Тестирование и оптимизация
└── examples/
    └── example-invoice-skill.md          # Пример готового скилла
```

## Calibrator

**Калибровщик промптов и ассистентов** — инженерная петля обратной связи для любых инструкций. Сравнивает AI-версию результата с авторской финальной редакцией, находит системные паттерны расхождений и формулирует конкретные правки в инструкцию.

### Что делает

Любой ассистент выдаёт 70–80% результата, остальное дорабатывается руками. И каждый раз — одни и те же правки. Калибровщик замыкает петлю: берёт две версии (AI и финальную), достаёт из дельты повторяющиеся паттерны, превращает их в точные дополнения к промпту. Через 5–10 итераций ассистент выдаёт ближе к финалу с первой попытки.

Работает с любыми ассистентами — текстовыми, кодовыми, аналитическими. Где есть «AI-версия» и «как должно быть» — там строится калибровка.

### Как устроена работа

| Шаг | Что происходит |
|-----|---------------|
| **1. Подготовка + анализ** | Читает текущую инструкцию и CHANGELOG, сверяет две версии блок за блоком |
| **2. Классификация** | Каждое расхождение — единичная правка / системный паттерн / рецидив |
| **3. Формулировка** | Для каждого паттерна — точный текст правки с примером «до/после» |
| **4. Применение** | Вносит правки в файл + обновляет CHANGELOG **или** выдаёт готовый блок для копирования |

### Два режима работы

Скилл сам определяет окружение и подстраивается:

- **Режим A (файловый)** — в Claude Code и VS Code, где есть доступ к файлам. Читает инструкцию, вносит правки прямо в файлы, ведёт `CHANGELOG.md`.
- **Режим B (диалоговый)** — в веб-чате Claude, ChatGPT, мобильном приложении. Автор вставляет две версии текстом, скилл возвращает таблицу паттернов и готовые формулировки правок для ручной вставки.

Один и тот же `SKILL.md` можно:
- подключить как скилл в Claude Code,
- загрузить инструкцией в Claude Project на claude.ai,
- вставить body как system prompt в любой LLM.

### Принципы

- **Сдержанность** — не каждая авторская правка превращается в правило. Паттерн = 2+ повторений или рецидив из истории
- **Конкретность** — правка = точный текст для вставки в инструкцию. Никаких «пиши естественнее»
- **Охота за рецидивами** — если правило уже было, но не сработало, диагностируй причину, а не добавляй третье поверх двух неработающих
- **Доменная нейтральность** — не привязан к конкретной области, работает с любым типом инструкций

### Установка

```bash
cp -r calibrator/ ~/.claude/skills/calibrator/
```

Или скопируйте в конкретный проект: `/path/to/project/.claude/skills/calibrator/`.

### Как использовать

Скажите Claude что-то вроде:

- «Откалибруй мой промпт — вот AI-версия, вот моя финалка»
- «Сравни две версии и предложи правки в инструкцию»
- «Почему ассистент всё время пишет одно и то же, как поправить скилл»

Скилл сам выяснит, какую инструкцию калибруем, и проведёт через все 4 шага с точками остановки.

### Структура

```
calibrator/
└── SKILL.md         # Самодостаточный протокол — весь скилл в одном файле
```

## Meme Maker

**Конструктор мемов-картинок** — превращает сырую идею в готовый мем с русскими надписями. Подбирает подходящий шаблон (Drake, Distracted Boyfriend, This is Fine, Galaxy Brain, Two Buttons, Spongebob, DiCaprio Cheers и ещё 18+), формулирует панчи и рисует через **Nano Banana 2 (Google Gemini)** по MCP-серверу.

### Что делает

Берёт мысль («вышел новый ChatGPT и DeepSeek, а я на Claude и спокоен») и собирает 5–7 шаблонов с готовыми русскими подписями. Ты выбираешь, какие рисовать — скилл генерирует параллельно. Поддерживает итерацию: перегенерация в том же контексте, точечная правка только текста через `gemini_edit_image`.

### Поток работы

| Шаг | Что происходит |
|-----|---------------|
| **0. Активация** | Один раз: проверяет MCP `nanobanana`, при отсутствии даёт инструкцию по установке + ссылку на Gemini API-key |
| **1–2. Парсинг + матчинг** | Извлекает структуру идеи (противопоставление, число элементов, эмоция), подбирает 5–7 шаблонов |
| **3. Список** | Показывает шаблоны с готовыми русскими подписями (не плейсхолдерами) |
| **4–7. Генерация** | После выбора пользователя рисует выбранные мемы параллельно, каждый в своей `conversation_id` |
| **8–9. Итерация** | Перегенерация, точечная правка текста, полный сброс контекста |

### Принципы

- **Сначала список, потом генерация** — пользователь сравнивает варианты текста до того, как потрачены вызовы API
- **Готовые подписи, не плейсхолдеры** — в списке всегда конкретный русский текст
- **Один conversation_id на один мем** — иначе Spongebob начинает держать кружку Drake
- **Нейтральный режим по умолчанию** — общечеловеческий юмор; авторский голос-профиль подключается опционально

### Установка

Скопируйте директорию в ваш проект или глобально:

```bash
cp -r meme-maker/ ~/.claude/skills/meme-maker/
```

Затем подключите MCP `nanobanana` (получите бесплатный ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey)):

```bash
claude mcp add nanobanana --env GOOGLE_AI_API_KEY=ВСТАВЬ_СВОЙ_КЛЮЧ -- npx -y @ycse/nanobanana-mcp@latest
```

Перезапустите Claude Code, и Meme Maker сам проведёт через первый запуск.

### Как использовать

Скажите Claude Code что-то вроде:

- «Сделай мем про то, что я три года на одной модели, а индустрия каждую неделю выкатывает новую»
- «Мем на тему — все ушли в Obsidian, а я на .txt»
- «Нарисуй мем: пишу пост сам vs даю Claude outline»

### Структура

```
meme-maker/
├── SKILL.md                              # Ядро + Шаг 0 активации MCP
├── README.md                             # Установка и инструкция
└── references/
    ├── meme_catalog.md                   # 18+ мем-шаблонов: формат, роли, под какие идеи
    ├── prompting_rules.md                # Правила промптов: английский, Russian Cyrillic, spatial-layout
    └── voice_profile.example.md          # Шаблон опционального авторского голоса-профиля
```

## Wordstat Collector

**Сборщик семантического ядра** — по одной фразе-маркеру и региону собирает список поисковых запросов с реальной частотностью Яндекс Wordstat через [Pixel Tools](https://tools.pixelplus.ru/) API. На выходе — `keys.xlsx` с классифицированными запросами и числом показов в месяц.

### Что делает

Берёт маркер («ремонт пластиковых окон») и регион, разворачивает ядро: парсит связанные запросы Wordstat, проверяет частотность каждого по нужному региону, отсекает «фантомы» (фразы без реального спроса), раскладывает по 6 категориям с оценкой релевантности и опционально кластеризует по подобию топа Яндекса. Принцип: каждый ключ подтверждён Wordstat — без проверки частотности 80–90% LLM-сгенерированного ядра оказывается мусором.

### Поток работы

| Шаг | Что происходит |
|-----|---------------|
| **0. Маркер + регион** | Минимальный бриф: главная фраза + lr-код региона |
| **1. Частотность seed'ов** | `wordstatapi` проверяет стартовые запросы, мёртвые отсекаются |
| **2. Расширение** | `wordstatapikeywords` парсит связанные запросы Wordstat — сразу с частотностью |
| **3. Классификация** | Claude раскладывает ключи по 6 категориям + релевантность 0–1 |
| **4. Кластеризация** (опц.) | `gruppirovka` группирует запросы по подобию топ-10 Яндекса |
| **5. Выгрузка** | `keys.xlsx` по категориям |

### Принципы

- **Только подтверждённый спрос** — каждый запрос проверен через Wordstat, фантомы отсекаются
- **Один источник данных** — только Pixel Tools, без сторонних LLM-сервисов и SERP-агрегаторов
- **Региональная точность** — частотность снимается по конкретному lr-коду, а не «в среднем»
- **Только сбор** — скилл собирает и выгружает семантику, не пишет тексты и не делает аудит

### Установка

```bash
cp -r wordstat-collector/ ~/.claude/skills/wordstat-collector/
cd ~/.claude/skills/wordstat-collector/
pip install httpx python-dotenv rapidfuzz openpyxl
cp .env.example .env   # впиши PIXELTOOLS_API_KEY
python scripts/smoke_test.py
```

Ключ Pixel Tools: [tools.pixelplus.ru](https://tools.pixelplus.ru/) → ЛК → API.

### Как использовать

Скажите Claude Code что-то вроде:

- «Собери семантику по запросу "доставка цветов" для Москвы»
- «Расширь ядро по маркеру и выгрузи в Excel»
- «Собери ключевые слова с частотностью Wordstat и кластеризуй по топу»

### Структура

```
wordstat-collector/
├── SKILL.md                       # Ядро скилла и workflow
├── README.md                      # Установка и состав
├── .env.example                   # Шаблон ключа
├── references/
│   ├── 01-discovery.md            # Маркер + регион (lr-коды)
│   ├── 02-keyword-research.md     # Логика сбора и кластеризации
│   └── 03-api-setup.md            # Pixel Tools setup, лимиты
└── scripts/
    ├── smoke_test.py              # Проверка ключа и зависимостей
    ├── wordstat_enrichment.py     # Частотность через wordstatapi
    ├── wordstat_expansion.py      # Расширение через wordstatapikeywords
    ├── clustering.py              # Кластеризация через gruppirovka
    └── export_xlsx.py             # Выгрузка в keys.xlsx
```

## Прохор — AI-маркетолог девелопера

**Маркетолог застройщика под ключ** для рынка недвижимости. Берёт объект (ЖК, апарты, БЦ, ТРЦ, гостиница, склад) и проводит сквозной пайплайн от анализа аудитории до готовых креативов с визуалами — деловой средне-жёсткий дискуссионный голос на профжаргоне девелопера, с источником под каждым числом и юрфильтром 214-ФЗ.

### Что делает

Берёт объект и доводит до пакета артефактов: сегменты ЦА с absorption-вердиктом → концепция кампании под стадию жизненного цикла → тексты креативов с двойной проверкой (антимодерация площадок + юрфильтр 214-ФЗ) → визуалы через Nano Banana / GPT Image 2. Каждое число несёт статус источника, гипотезы помечаются, выдумок нет — на рынке, где врать про доходность запрещено законом.

### Пайплайн (must-have, всегда полностью)

| Этап | Что происходит |
|------|---------------|
| **1. Анализ аудитории** | 4–6 сегментов под тип объекта (JTBD, триггеры, барьеры) + absorption-вердикт по 3 числам: давить конверсию или снимать performance-газ |
| **2. Концепция** | Позиционирование, ключевые сообщения, креативные углы, tone-of-voice под стадию (котлован → монолит → отделка → сдача → остатки) |
| **3. Тексты** | Заголовки, объявления, CTA под форматы; каждый текст — двойная проверка до показа, нарушение переформулируется по схеме «было → стало» |
| **4. Визуалы** | Промпты и генерация баннеров в 1:1, 4:5, 9:16, 16:9 с роутингом моделей под задачу |

### Принципы

- **Каждое число = объект со статусом** — `[✓ источник]` / `[◐ гипотеза → A/B]` / `[△ требует подтверждения]`, нет источника — нет числа
- **Юрфильтр 214-ФЗ** поверх антимодерации площадок — запрет обещаний доходности, «апартаменты ≠ квартира», маркировка ОРД/erid
- **Контрольные точки с развилкой** — не «согласен?», а 2 именованных маршрута с ценой каждого решения
- **Демо-режим для сцены** — отдельный слой поверх рабочего продукта для конференций и вебинаров

### Установка

```bash
cp -r prohor-ai-marketer/ ~/.claude/skills/prohor/
```

Для визуалов подключите MCP `nanobanana` (см. `prohor-ai-marketer/README.md`).

### Как использовать

Скажите Claude Code что-то вроде:

- «Прохор, сделай кампанию для ЖК комфорт-класса в Питере»
- «Маркетолог девелопера — разбери вот этот объект по ссылке и собери концепцию»
- «Деморежим» — для показа на сцене

### Структура

```
prohor-ai-marketer/
├── SKILL.md                  # Ядро скилла, триггеры, критические правила
├── README.md                 # Полный обзор и установка
├── LICENSE                   # MIT
├── references/               # Дисциплина диалога, голос, пайплайн, режимы, демо, модерация, визуалы
├── library/                  # Верифицированные данные (каналы, ЦА, воронки, бенчмарки)
├── prompts/                  # Шаблоны промптов визуалов
├── scripts/                  # export_docx.py — рендер артефактов в фирменный .docx
└── examples/                 # Эталонный сквозной кейс ЖК комфорт-класса
```

Прохора можно переделать под любую нишу: каркас универсален, под недвижимость его делают `library/` и `references/`.

Отдельная благодарность **Артёму Гусеву** — маркетологу для девелоперов — за помощь в создании образа Прохора.

## Иннокентий (Кеша)

**Креативный директор** — генерирует рекламные креативы для digital-платформ (Яндекс Директ, VK Ads). Живой спорящий персонаж: аргументирует, не соглашается с первой попытки, но финальное слово за пользователем.

### Что делает

Полный конвейер: анализ ЦА → концепция (BIG IDEA с блоком «где может не сработать») → тексты объявлений с антимодерацией → визуалы через Nano Banana → экспорт в Excel / Google Sheets. Накапливает библиотеку продуктов и аудиторий между сессиями (в публичной версии — пустую).

### Установка

```bash
cp -r ad-creative-kesha/ ~/.claude/skills/ad-creative-kesha/
```

Подробности — в `ad-creative-kesha/README.md`.

## Рисовальщик (risovalshchik)

**Универсальный генератор изображений** — рисует через Nano Banana 2 (Google Gemini) или GPT Image 2 (OpenAI). При запуске спрашивает модель, сохраняет результат в `~/Downloads/images`.

### Что делает

Одиночные картинки, серии в едином стиле (рецепты, пошаговые гайды), кириллический текст на изображении, продакт-плейсмент через доноров упаковок. Требует Nano Banana MCP; для GPT Image 2 — свой `OPENAI_API_KEY` в `.env` (в репозитории его нет).

### Установка

```bash
cp -r risovalshchik/ ~/.claude/skills/risovalshchik/
```

Подробности — в `risovalshchik/README.md`.

## Telegram

**Курьер с обязательным согласованием** — транспорт в Telegram от личного аккаунта пользователя поверх Telethon-сессии: отправить текст в чат, найти чат, прочитать последние сообщения.

### Главное правило

Ни одно сообщение не уходит без явного согласия пользователя в текущем диалоге: перед отправкой скилл показывает карточку (чат + текст 1:1) и ждёт «да». Секреты (api_id/api_hash, файл сессии) **не входят в репозиторий** — настраиваются локально по `telegram/references/setup.md`.

### Установка

```bash
cp -r telegram/ ~/.claude/skills/telegram/
```

Подробности — в `telegram/README.md`.

## Fact-Checker Pro

**Промышленный фактчекер** — берёт статью (текст, URL или файл) и выдаёт таблицу проверки: каждое утверждение со статусом «Истинно» / «Ложно» / «Неясно», реальными источниками и вердиктом о надёжности материала.

### Что делает

Конвейер 7 шагов: приём входа → чеклист-план → декомпозиция на атомарные утверждения → верификация (WebSearch находит ≥3 источника, WebFetch **открывает каждый URL**) → таблица → вердикт-саммари → выгрузка (`.md`, опционально Google Sheets / Excel).

### Фишки

- **Антигаллюцинация ссылок** — статус не ставится без реально открытой ссылки; не открылось → «Неясно» + N/A, а не фейковый URL.
- **Классификация утверждений** — факт / оценка / мнение / прогноз; субъективные фразы не ловят ложное «Ложно».
- **Тир источников (T1–T4)** — три блога ≠ три независимых авторитетных источника.
- **Приоритет + уверенность** по каждому факту и **итоговый вердикт** с красными флагами.

### Установка

```bash
cp -r fact-checker-pro/ ~/.claude/skills/fact-checker-pro/
```

Подробности — в `fact-checker-pro/README.md`.

## Skill Revision Spec

**Ревизия ваших скиллов по новым правилам Claude 5** — не скилл, а текстовое задание для агента: кладёте в проект, просите план, получаете разбор того, что в ваших инструкциях устарело, дублируется и противоречит друг другу.

### Что делает

Anthropic удалили больше 80% системного промпта Claude Code без потерь на своих тестах и [описали, что изменилось](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models). Документ переносит эти выводы на ваш проект: ищет правила, которые предписывают метод вместо цели, дубли одной нормы в трёх файлах, запреты от старых моделей, блоки, которые грузятся всегда, а нужны раз в месяц, и описания словами там, где можно показать образец.

### Безопасность

Не удаляет файлы, не трогает триггеры и контракты, не ослабляет защитные правила, не открывает файлы с ключами, не делает commit и push, не запускает скиллы с внешними действиями. По умолчанию — режим разбора: без явного разрешения не меняет ничего. Правки применяет по одному номеру, способ отката пишет сразу.

### Установка

```bash
cp skill-revision-spec/SKILL-REVISION-SPEC.md /path/to/your/project/
```

Дальше в Claude Code:

```
Прочитай SKILL-REVISION-SPEC.md и выполни ревизию по нему.
Область: ОДИН СКИЛЛ skills/мой-скилл
Права:   ТОЛЬКО ОТЧЁТ
```

Подробности, ограничения и честный список того, чего документ не умеет, — в `skill-revision-spec/README.md`.
