# Прохор — AI-маркетолог девелопера

Claude Code скилл: маркетолог застройщика под ключ для рынка недвижимости. Берёт объект (ЖК, апарты, БЦ, ТРЦ, гостиница, склад, стрит-ритейл) и проводит сквозной пайплайн — от анализа аудитории до готовых креативов с визуалами.

> Прохор: «Я не пишу красивые слова под картинку. Я считаю absorption, спорю про сегмент, режу обещания доходности по 214-ФЗ и ставлю источник под каждое число. Реклама недвижимости судится за каждую цифру — поэтому выдумок тут не будет.»

Голос — деловой средне-жёсткий дискуссионный, на профжаргоне девелопера (absorption, эскроу, ДДУ, квартирография, tenant-mix). Прохор аргументирует и спорит, но финальное слово всегда за пользователем.

---

## Что делает Прохор

Базовый пайплайн (must-have, всегда полностью):

1. **Анализ аудитории** — 4–6 сегментов ЦА под тип объекта (JTBD, триггеры, барьеры) + absorption-вердикт по 3 числам (объём экспозиции, продано за N месяцев, срок сдачи): давить конверсию или снимать performance-газ.
2. **Концепция кампании** — позиционирование, ключевые сообщения, креативные углы, tone-of-voice, привязанные к стадии жизненного цикла объекта (котлован → монолит → отделка → сдача → остатки).
3. **Тексты креативов** — заголовки, объявления, CTA под форматы; каждый текст проходит двойную проверку до показа: антимодерация площадок + юрфильтр 214-ФЗ. Нарушение не выкидывается, а переформулируется с тем же драйвом по схеме «было → стало».
4. **Визуалы** — промпты и генерация баннеров через Nano Banana / GPT Image 2 в форматах 1:1, 4:5, 9:16, 16:9 с роутингом моделей под задачу. По умолчанию графика отдаётся чистой, без знака на изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях. Впечатать watermark в пиксель — опционально, по явному запросу.

Опционально (по запросу): детальная воронка длинной сделки с лагами эскроу/ДДУ, медиа-микс (доли %, не рубли), актуализация бенчмарков через WebSearch, кейсы конкурентов, расширенные форматы, параллельная генерация в двух моделях, кириллический текст на изображении через GPT Image 2, экспорт в Google Workspace.

**Объём v1:** жильё + апарты отработаны полностью. Коммерция (БЦ, ТРЦ, склады, гостиницы; tenant-mix, NOI, вакантность) — ранний контур: пресеты в библиотеке есть, но данные помечаются как требующие верификации.

## Требования к окружению

| Компонент | Статус | Зачем |
|---|---|---|
| **Nano Banana MCP** (`nanobanana`) | **обязателен для визуалов** | генерация изображений (этап 4), `gemini_generate_image` / `gemini_edit_image` |
| **GPT Image 2** | желателен | кириллический текст на постерах, дуэль моделей; без него работает только Nano Banana |
| **WebSearch / WebFetch** | встроенные | актуализация бенчмарков, разбор объекта по ссылке (режим B), поиск упоминаний (режим C). Доп. установка не нужна |
| **Google Workspace MCP** | опционально | экспорт артефактов в Drive/Sheets/Docs |

> Если Nano Banana недоступен, этапы 1–3 отрабатывают полностью; этап 4 выдаёт только промпты с пометкой, что генерация не выполнена.

## Установка

Скилл лежит папкой в коллекции [claude-skills](https://github.com/TimurUgulava/claude-skills). Скопируйте папку в каталог скиллов Claude Code:

```bash
git clone https://github.com/TimurUgulava/claude-skills.git
cp -r claude-skills/prohor-ai-marketer ~/.claude/skills/prohor
```

(для проектного скилла — в `.claude/skills/prohor/` внутри репозитория проекта).

Подключите MCP `nanobanana` для генерации визуалов (бесплатный ключ — на [aistudio.google.com/apikey](https://aistudio.google.com/apikey)):

```bash
claude mcp add nanobanana --env GOOGLE_AI_API_KEY=ВСТАВЬ_СВОЙ_КЛЮЧ -- npx -y @ycse/nanobanana-mcp@latest
```

Для кириллических постеров через GPT Image 2 нужен скилл-генератор с OpenAI-ключом (см. `references/image-generation.md`). Без него Прохор работает на одном Nano Banana с оговоркой про риск текста на изображении.

Для экспорта артефактов в `.docx`:

```bash
pip install python-docx
```

После установки скилл активируется по триггерам — отдельного включения не требуется.

## Запуск (триггеры активации)

Прохор включается на фразы и контекст недвижимости:

- по имени: **«Прохор»**, «маркетолог девелопера»;
- по задаче: «рекламная кампания ЖК», «креативы для недвижимости», «продвижение апартаментов», «кампания для БЦ / ТРЦ», «реклама новостройки», «анализ ЦА объекта недвижимости», «баннеры для застройщика», «медиа-микс для девелопера»;
- по демо: «деморежим», «демо», «демонстрационный режим», «покажи на сцене».

Также активируется, когда пользователь просит маркетинг под конкретный объект недвижимости.

**Когда НЕ включать:** реклама товаров и услуг вне недвижимости, SEO/GEO страниц сайта, медиабаинг и закупка рекламы, финансовая модель проекта.

## Первый запуск

1. **Назовите объект и дайте источник фактов.** Прохор сначала определяет режим входа — от него зависит статус каждого факта:
   - **A** — есть бриф / презентация / описание → факты идут со словами заказчика;
   - **B** — есть ссылка на сайт объекта → Прохор разбирает её через **WebFetch**, собранное помечает `[△ требует подтверждения]`;
   - **C** — только название или адрес → ищет упоминания через **WebSearch**, статус тот же `[△ требует подтверждения]`;
   - **D** — гипотетический пример (демо / тренировка) → `[◐ гипотеза]`.
2. **Подтвердите паспорт объекта.** В режимах B/C/D Прохор показывает черновой паспорт со статусами и спрашивает, что править. Без подтверждения пайплайн не идёт дальше этапа 1.
3. **Проходите этапы по одному.** После этапов 1 и 2 — контрольная точка: не «согласен?», а развилка с ценой каждого маршрута (чек, цена лида, длина цикла, конкуренция) + слот «свой вариант». Следующий артефакт строится под выбор.

> Совет: чем подробнее бриф (квартирография, цены с источником, стадия, темп продаж), тем меньше Прохор помечает `[△]` и тем точнее absorption-вердикт.

## Демо-режим (сцена: конференции, форумы, вебинары)

Демо — отдельный слой ПОВЕРХ рабочего продукта. Пайплайн не меняется, меняется только подача: Прохор говорит с залом.

**Как войти:** явной командой ведущего — «деморежим», «демо», «демонстрационный режим», «запускай демо», «покажи на сцене». Само по себе демо не включается.

**Как подготовить показ:** демо идёт только на **реальном объекте**. Перед выступлением прогоните Прохора заранее на своём объекте в обычном рабочем режиме — он соберёт папку сессии с настоящими паспортом, сегментами, концепцией и текстами; демо-режим читает эту папку. На сцене Прохор:

- честно проговаривает: исследование проведено заранее, смотрим результат;
- нарратит **по одному этапу за реплику** и заканчивает словом «**Продолжаем?**» — следующий этап только после подтверждения со сцены;
- держит темпо-партитуру: пауза под реакцию, вопрос залу, reveal закэшованного;
- НЕ называет вслух имена файлов и технические детали.

**Жёсткий инвариант сцены:** у каждого живого действия есть оффлайн-двойник, который выходит первым. Падает лайв (WebSearch, генерация) — работаем по кэшу, нарратив цел.

Эталон структуры сессии (на вымышленном объекте ЖК «Пример») — `examples/case-zhk-comfort.md`. Партитура этапов, развилки А/Б/В, дуэль моделей и банк Q&A — `references/demo-mode.md`.

## Как обновлять библиотеку каналов

Каналы Прохор берёт только из верифицированной библиотеки `library/channels/` — он не выдумывает площадки.

| Файл | Категория |
|---|---|
| `library/channels/performance.yaml` | Яндекс.Директ, VK Ads, MyTarget |
| `library/channels/social.yaml` | VK SMM, Telegram, Дзен, мессенджеры |
| `library/channels/classified.yaml` | Авито, Циан, Домклик, Яндекс Недвижимость |
| `library/channels/brand-offline.yaml` | DOOH, наружка, ТВ, радио, инфлюенс |
| `library/channels/commercial-b2b-hospitality.yaml` | B2B-каталоги, деловые издания, системы бронирования (ранний контур) |

**Правило по числам (ядро доверия):** каждый бенчмарк — это объект `{значение, тип_источника, ссылка_или_запрос, дата_актуализации, статус}`. Допустимые типы источника: `verified-library`, `web-search`, `hypothesis`. Нет надёжных данных — пишем «нет надёжных данных, нужен пилот», число не выдаём.

Чтобы добавить или обновить канал: найдите нужный YAML по категории, скопируйте существующую карточку как образец схемы, проставьте по каждому числу `тип_источника`, `ссылка_или_запрос`, `дата_актуализации` (`YYYY-MM-DD`) и `статус`. Новый, ещё не верифицированный канал помечайте как эксперимент. Шаблоны WebSearch-запросов — `references/research-actualization.md`.

## Анти-галлюцинационные принципы (коротко)

Это не украшение, а фундамент работы на рынке, где врать про доходность запрещено законом.

- **Каждое содержательное число = объект со статусом.** Из этого — инлайн-токены `[✓ источник]` / `[◐ гипотеза → A/B]` / `[△ требует подтверждения]` / `[▢ AI-визуализация]`, раскрытие по запросу и финальная аудит-стена «Чего Прохор НЕ выдумал».
- **Нет источника — нет числа.** Прохор пишет «нет надёжных данных, нужен пилот» и даёт диапазон со ссылкой.
- **Факты об объекте — со слов заказчика;** собранное в режимах B/C — `[△ требует подтверждения]`. Стратегия — гипотеза. Бюджеты — доли %, не рубли.
- **Юрфильтр 214-ФЗ** поверх антимодерации площадок: запрет обещаний доходности и прироста цены (особенно апарты/ДДУ), «апартаменты ≠ квартира», цена/ипотека без проектной декларации и банка, «от застройщика» без юрлица/ОГРН, маркировка ОРД/erid.

Подробности — `SKILL.md` и `references/communication-style.md`.
