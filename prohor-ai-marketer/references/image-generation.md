# Генерация визуалов: Nano Banana / GPT Image 2

Точная интеграция этапа 4. Две модели, два транспорта: **Nano Banana 2** (Google, через MCP `nanobanana`) и **GPT Image 2** (OpenAI, через скрипт `risovalshchik`). Промпт-шаблоны под недвижимость — `prompts/creative-prompts.md` (текстовый каркас для обеих моделей, включая кириллический постер); полная команда GPT Image 2 — ниже, раздел «Вариант Б: GPT Image 2». Опциональное впечатывание watermark по запросу заказчика — раздел «Watermark „AI-визуализация“ (опция)» ниже в этом файле. Опция строить креатив не с нуля, а на **оригинальной графике объекта** (рендеры с сайта застройщика, ассеты заказчика) как визуальном референсе — раздел «Генерация по референсам» ниже.

Жёсткие инварианты, которые не нарушаются никогда:
- **Каждое изображение помечается текстовым токеном `[▢ AI-визуализация]`.** Это не фото объекта. По умолчанию графика отдаётся чистой, без знака на самом изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой (выдача, `campaign_matrix`), а не в пикселях. Митигация самого чувствительного риска рекламы недвижимости. Впечатать watermark в пиксель — опционально, только по явному запросу заказчика.
- **Промпт — всегда на английском.** Качество обеих моделей на русском промпте заметно ниже. Текст, который должен попасть НА картинку (заголовок, цена, «Старт продаж») — в двойных кавычках + явный маркер языка.
- **Сохранение — в `~/Downloads/images/prohor/zhk-demo/`** (slug демо-объекта). Для реального заказчика — `~/Downloads/images/prohor/<slug-объекта>/`.

## Роутинг моделей под задачу

Выбор модели — осознанный, под конкретный креатив, а не по умолчанию. Обоснование проговаривается пользователю одной строкой.

| Задача креатива | Модель | Почему |
|---|---|---|
| Атмосферный фасад, dusk-свет, среда квартала, видовая квартира, благоустройство | **Nano Banana 2** | Thinking-ядро держит spatial/физику и свет, фотореализм атмосфернее, дешевле, есть edit-сессия для мульти-ratio |
| Постер-наружка с заголовком и ценой числами, «Старт продаж», плашка с условиями | **GPT Image 2** | Уверенно рисует кириллицу на тексте — на чём Nano Banana системно плывёт на длинных словах |
| Серия форматов от одного эталонного кадра (1:1 → 4:5 → 9:16 → 16:9) | **Nano Banana 2** | `conversation_id` + `gemini_edit_image` от `history:0` держат единый фасад/свет между форматами |
| Прозрачный фон под наложение в вёрстке | **GPT Image 2** | Нативный `--transparent` |
| 2K-разрешение под премиум-площадку | **GPT Image 2** | до 2048×2048; Nano Banana 2 в этом стеке — стандартное разрешение |

**Правило кириллицы (общее для обеих моделей):** длинный русский текст на картинке системно ломается, у Nano Banana особенно (буквы пляшут, слог пропадает). Поэтому:
- текст на постере — через **GPT Image 2**;
- на Nano Banana допустимы только числа («215 тыс. ₽/м²»), латинские термины и очень короткие русские слова (до ~7 символов: «Цена», «Старт»);
- если кириллица поплыла и на GPT Image 2 — режем заголовок на короткие или выносим текст в плашку вёрстки, не итерируем по 5 раз.

> Голос Прохора в реплике-обосновании: «Постер с ценой и „Старт продаж“ беру на GPT Image 2 — он чисто кладёт кириллицу. Атмосферу залива на dusk-фасаде отдам Nano Banana, у неё свет живее. Это роутинг под задачу, а не „какая под рукой“.»

## Форматы (aspect ratio)

Базовый пакет этапа 4: **1:1, 4:5, 9:16, 16:9**. Расширенный (опция «расширенные форматы»): DOOH 6:1, карточки 3:4, Stories 9:16.

| Формат | Назначение | Nano Banana (`set_aspect_ratio`) | GPT Image 2 (`--size`) |
|---|---|---|---|
| 1:1 | Лента VK, карточка классифайда, превью | `1:1` | `1024x1024` / `2048x2048` |
| 4:5 | Вертикаль в ленте (VK/соцсети) | `4:5` | `1024x1536` (близко) |
| 9:16 | Stories, Reels, вертикальный экран | `9:16` | `1024x1536` / `1536x2048` |
| 16:9 | DOOH, ландшафтный баннер, YouTube | `16:9` | `1536x1024` / `2048x1536` |

GPT Image 2 не имеет точного 4:5 — берём `1024x1536` (2:3) как ближайший портрет; если критична именно 4:5, кадрируем в вёрстке. 2K-размеры (`2048x*`) работают только на `gpt-image-2`; при fallback на `gpt-image-1` берём 1024-ряд.

## Вариант А: Nano Banana 2 (MCP `nanobanana`)

Инструменты MCP и их роли:

| Инструмент | Назначение |
|---|---|
| `mcp__nanobanana__set_model` | модель ядра: `flash` (быстро/дёшево) или `pro` (`gemini-3-pro-image-preview`, точнее на тексте и spatial). Для постеров и видовых — `pro` |
| `mcp__nanobanana__set_aspect_ratio` | формат кадра перед генерацией (`1:1`/`4:5`/`9:16`/`16:9`) |
| `mcp__nanobanana__gemini_generate_image` | генерация эталонного кадра по промпту |
| `mcp__nanobanana__gemini_edit_image` | правка/пере-кадрирование от референса (`image_path: "history:0"`) |
| `mcp__nanobanana__get_image_history` | список кадров сессии (нужен индекс `history:0` — эталон) |
| `mcp__nanobanana__clear_conversation` | сброс сессии перед новой независимой задачей |

### Процедура

**Шаг 1. Сброс и настройка сессии.** `conversation_id` всегда = slug объекта, не `default` — это изолирует кампанию.

```
mcp__nanobanana__clear_conversation   conversation_id: zhk-demo
mcp__nanobanana__set_model            model: pro            # видовые/постеры
mcp__nanobanana__set_aspect_ratio     aspect_ratio: 16:9    # стартовый формат эталона
```

**Шаг 2. Эталонный кадр** (один креатив = один эталон, от него потом все форматы):

```
mcp__nanobanana__gemini_generate_image
  conversation_id: zhk-demo
  prompt:      <финальный английский промпт из prompts/creative-prompts.md>
  output_path: ~/Downloads/images/prohor/zhk-demo/dusk-facade-16x9.png
```

По умолчанию промпт идёт без watermark-суффикса — графика отдаётся чистой. Watermark-суффикс добавляется к промпту только по явному запросу заказчика (опция — раздел «Watermark „AI-визуализация“ (опция)» ниже в этом файле); в этом случае к имени файла можно добавить суффикс `-ai-viz`.

**Шаг 3. Остальные форматы — `gemini_edit_image` от `history:0`** (от эталона, не от предыдущего — иначе фасад дрейфует через 2–3 кадра):

```
mcp__nanobanana__set_aspect_ratio   aspect_ratio: 9:16
mcp__nanobanana__gemini_edit_image
  conversation_id: zhk-demo
  image_path:  "history:0"          ← фиксируем эталон
  edit_prompt: Maintain the EXACT same building facade, same dusk lighting,
               same waterfront environment, same color palette as the reference.
               Re-frame to vertical 9:16 for Stories.
  output_path: ~/Downloads/images/prohor/zhk-demo/dusk-facade-9x16.png
```

> Строку `Keep the "AI-визуализация" watermark in the corner.` добавляй в `edit_prompt` только если заказчик явно попросил впечатанный watermark (опция). По умолчанию её нет — кадр остаётся чистым.

**Якорный блок** в `edit_prompt` при пере-кадрировании перечисляй конкретно: «same building facade, same dusk light, same waterfront, same palette». Общее «in the same style» модель интерпретирует слабо и плывёт. Меняешь только кадрирование — фасад остаётся тем же зданием.

**Правки от пользователя** («сделай вечер темнее», «добавь подсветку входа», «озелени двор») — тоже `gemini_edit_image` от `history:0`, не от `last`. Картинка слушается слов, оставаясь тем же объектом.

## Вариант Б: GPT Image 2 (скрипт `risovalshchik`)

> ВАЖНО: перед первым вызовом **прочитай `risovalshchik`** (`~/.claude/skills/risovalshchik/SKILL.md` и `scripts/generate_gpt_image.py`), чтобы взять актуальный путь скрипта и набор флагов — они могут обновиться независимо от Прохора. Ниже — зафиксированный на момент сборки контракт.

Путь скрипта: `~/.claude/skills/risovalshchik/scripts/generate_gpt_image.py`. Ключ читается из `.env` в корне `risovalshchik`.

Флаги:

| Флаг | Значение |
|---|---|
| `--prompt` | финальный английский промпт (обязательный) |
| `--size` | `1024x1024` `1024x1536` `1536x1024` `2048x2048` `1536x2048` `2048x1536` `auto` |
| `--n` | число вариантов 1–10 (для батча — см. ниже) |
| `--quality` | `low` `medium` `high` `auto` (по умолчанию `high`) |
| `--model` | `gpt-image-2` (по умолчанию; при 403-verification автооткат на `gpt-image-1`) |
| `--reference` | путь к референсу (можно несколько; переключает на edits endpoint) |
| `--output-dir` | **папка** сохранения — задаём slug-папку объекта |
| `--transparent` | прозрачный фон (PNG) |
| `--output-format` | `png` `jpeg` `webp` |

Скрипт принимает `--output-dir` (директорию), а не путь к файлу — имя файла он формирует сам и печатает JSON с путями. По умолчанию `--prompt` идёт без watermark-суффикса. Если заказчик явно попросил впечатанный watermark (опция), суффикс кладём в `--prompt`, а не в имя.

### Постер-наружка с кириллицей (типовая задача GPT Image 2)

```bash
python3 ~/.claude/skills/risovalshchik/scripts/generate_gpt_image.py \
  --prompt "Photorealistic outdoor billboard mockup of a comfort-class residential complex by the waterfront at dusk. The headline reads \"КВАРТАЛ У ЗАЛИВА\" in Russian Cyrillic letters, bold condensed sans-serif, white, top of the frame. A price plate at the bottom reads \"от 215 000 ₽/м²\" and \"СТАРТ ПРОДАЖ\" in Russian Cyrillic letters. Clean composition, no extra text." \
  --size 2048x1536 \
  --quality high \
  --output-dir ~/Downloads/images/prohor/zhk-demo
```

По умолчанию в промпте нет блока угловой плашки `"AI-визуализация"` — постер отдаётся чистым. Если заказчик явно попросил впечатанный watermark (опция), добавь в `--prompt` блок `A small semi-transparent corner watermark reads \"AI-визуализация\" in Russian Cyrillic letters, lower-right.`

Кириллица — точный текст в кавычках + `in Russian Cyrillic letters` после каждого блока. Без маркера языка модель нарисует латиницу/транслит даже при русском замысле. Цена — числами (это разрешено), но без обещаний доходности и без ставки ипотеки без банка/декларации (юрфильтр 214-ФЗ, `references/moderation-rules.md`).

### Итерация по эталону

GPT Image 2 не держит сессию — каждый вызов независимый. Для правки передавай прошлый файл через `--reference` (можно несколько):

```bash
python3 .../generate_gpt_image.py \
  --prompt "Reproduce the same facade, same dusk light, same palette as the reference. Re-frame to vertical 9:16." \
  --reference ~/Downloads/images/prohor/zhk-demo/poster-16x9.png \
  --size 1024x1536 --quality high \
  --output-dir ~/Downloads/images/prohor/zhk-demo
```

Референсом бери эталон, не предыдущий кадр — иначе ошибки накапливаются и сцена плывёт.

## Генерация по референсам: оригинал объекта как визуальная база (опция)

По умолчанию обе модели работают text-to-image и рисуют **абстрактный** «дом у воды». Опция: подать на вход **оригинальную графику объекта** — официальный рендер или фото фасада с сайта застройщика, визуализацию из брифа/презентации, генплан, планировку, логотип, фото локации — как визуальный референс, чтобы креатив строился на **реальном облике конкретного ЖК**, а не на выдумке. Для недвижимости узнаваемость объекта критична: баннер на настоящем фасаде конвертит точнее и снимает расхождение «реклама ≠ то, что человек увидит на показе».

**Когда включать:** команда заказчика — «возьми рендеры с сайта», «на базе наших визуализаций», «используй ассеты как референс»; либо Прохор сам предлагает опцию в режиме B (есть ссылка на сайт) или когда заказчик дал ассеты. По умолчанию опция выключена.

### Откуда берём референсы

- **Режим B (ссылка на сайт).** При WebFetch Прохор фиксирует URL официальной графики (рендеры фасада, генплан, видовые, планировки) и по запросу скачивает их в `~/Downloads/images/prohor/<slug>/refs/`.
- **Бриф / презентация (режим A).** Изображения из PDF или презентации застройщика.
- **Подгрузка ассетов заказчика.** Заказчик даёт файлы напрямую: логотип, фирменные рендеры, фотосессия.
- **Другой артефакт.** Паспорт со ссылками на графику, макеты прошлой кампании.

### Два типа привязки к референсу

| Тип | Что берём из референса | Когда |
|---|---|---|
| **Identity / subject** (сильная привязка) | точный фасад, планировку, облик конкретного объекта | основной кейс недвижимости — узнаваемый ЖК на баннере |
| **Style / mood** (слабая привязка) | палитру, свет, ракурс, настроение фирменной графики; субъект свой | когда нужен только тон, а сюжет другой |

### Как технически

**GPT Image 2** — флаг `--reference <path>` (можно несколько; переключает на edits endpoint). Подаём 1–3 референса (фасад + деталь + логотип). Промпт описывает, что взять с референса и что добавить (свет, среда, текст, формат):

```bash
python3 ~/.claude/skills/risovalshchik/scripts/generate_gpt_image.py \
  --prompt "Use the building facade and architecture from the reference image as the exact subject. Keep proportions, materials and glazing faithful to the reference. Re-light to warm dusk, add blue-hour sky and a calm sea horizon. Do not invent floors, balconies or amenities that are not in the reference." \
  --reference ~/Downloads/images/prohor/<slug>/refs/facade-official.jpg \
  --size 1536x1024 --quality high \
  --output-dir ~/Downloads/images/prohor/<slug>
```

**Nano Banana** — `gemini_edit_image` с `image_path` = путь к реальному рендеру (вместо `history:0`). Оригинал становится эталоном серии, дальше форматы пере-кадрируются edit-ом уже от него:

```
mcp__nanobanana__gemini_edit_image
  conversation_id: <slug>
  image_path:  ~/Downloads/images/prohor/<slug>/refs/facade-official.jpg
  edit_prompt: Use this exact building as the subject. Maintain the EXACT facade,
               proportions and materials from the reference. Re-light to dusk,
               add warm window glow and waterfront. Do NOT add anything not in the reference.
  output_path: ~/Downloads/images/prohor/<slug>/dusk-facade-16x9.png
```

Дальше серию форматов держим edit-ом от этого кадра (`history:0`), якорный блок — «same building as the reference».

### Дисциплина (юрфильтр + ядро доверия) — обязательна

- **Права на референс — на заказчике.** Прохор не тащит случайные картинки из сети как референс: чужой рендер, фото с людьми, брендами или объектами конкурентов — это копирайт и модерация. Референс — только официальная графика заказчика/застройщика (его сайт, его презентация, его фотосессия).
- **Результат всё равно `[▢ AI-визуализация]`.** Даже построенный на реальном рендере застройщика креатив — это сгенерированная картинка, не фото готового объекта. Токен остаётся, риск «выдают за фото» референсом не снимается.
- **Не дорисовывать несуществующее** поверх реального облика — этажи, набережную, инфраструктуру, которых нет в проекте. Это усиление инварианта «никаких выдуманных фактов в кадре» (`prompts/creative-prompts.md`).
- **Фиксируем в `campaign_matrix`**, что креатив построен на референсе и на каком источнике.

> Голос Прохора: «Строить баннер на реальном рендере с сайта — правильно: объект узнаваемый, а не абстрактный дом у воды, и реклама бьётся с тем, что человек увидит на показе. Но три вещи. Права на исходник — твои, чужие картинки из сети я в референс не тащу. Это всё равно `[▢ AI-визуализация]`, не фото сданного дома. И что не нарисовано в проекте — поверх рендера не пририсую, даже если просят „покрасивее“.»

## Watermark «AI-визуализация» (опция)

По умолчанию графика отдаётся чистой, без знака на самом изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях. Впечатать watermark в пиксель — опционально, только по явному запросу заказчика.

Когда заказчик явно попросил впечатанный watermark, логика такая (полный промпт-суффикс — `prompts/creative-prompts.md`, раздел «Watermark-суффикс»):

- В промпт (обе модели) добавляется блок: впечатать в нижний угол деликатный полупрозрачный знак `"AI-визуализация" in Russian Cyrillic letters, small, semi-transparent, lower-right corner`.
- Watermark тогда **в пикселе**, не подпись в чате — не теряется при пересылке макета.
- Можно продублировать в имени файла суффиксом `-ai-viz` и в строке `campaign_matrix` отметить, что watermark впечатан по запросу.

> Голос Прохора: «По умолчанию картинку отдаю чистой — без знака в пикселе. Честный дисклеймер „это AI-визуализация, а не фото дома“ ставлю текстовым токеном `[▢ AI-визуализация]` рядом с картинкой в выдаче. Если заказчик просит вшить watermark прямо в пиксель — впечатаю, это его выбор и его ответственность.»

## Параллельная генерация двумя моделями (опция / демо-фича)

Команда пользователя «параллельно обе». Один промпт уходит **одновременно** в обе модели — в одном блоке вызовов без ожидания между ними:

1. `mcp__nanobanana__gemini_generate_image` с промптом dusk-фасада;
2. в том же блоке — `python3 .../generate_gpt_image.py --prompt "<тот же промпт>" --size 1536x1024 --output-dir <slug-папка>`.

Оба PNG рендерятся бок о бок. Применение:
- **Реальная сессия** — пользователь выбирает лучший результат под ЦА, Прохор даёт профразбор (где чище кириллица, где живее свет).
- **Демо (blind-duel)** — оба кадра показываются без подписей, зал голосует, потом reveal моделей. Процедура — `references/demo-mode.md`. На сцене из кэша первым выходит закэшованный двойник пары (двойной буфер), лайв догоняет.

Типовой профразбор после reveal (фактура, не выдумка про конкретный кадр — формулировки проверяются на самом результате): GPT Image 2 обычно чище кладёт кириллицу на плашке → берём под постеры с ценой; Nano Banana обычно даёт атмосфернее свет, но длинный текст плывёт → берём под фасады без надписей.

## Батчи

Чтобы не упереться в лимиты и держать контроль качества — генерируем **батчами по 3**:

- **GPT Image 2** — `--n 3` за один вызов (до 10, но 3 — рабочий батч: проще отобрать).
- **Nano Banana** — три последовательных `gemini_generate_image` в одной сессии (вариативность), либо три `gemini_edit_image` от `history:0` под три формата.

После каждого батча — показ результата через Read и контрольная точка, дальше следующий батч. Не гнать 12 картинок без просмотра.

## Fallback: MCP молчит / скрипт упал

Если `mcp__nanobanana__*` не отвечает или таймаутит, а GPT Image 2 вернул ошибку — **не сочиняй, что картинка сгенерирована.** Выписываешь промпты текстом, чтобы пользователь прогнал их сам, и честно говоришь, что генерация не выполнена.

```
Генерация не прошла (MCP/скрипт недоступен). Промпты под ручной прогон:

[1] Nano Banana 2, формат 16:9, dusk-фасад:
    <финальный английский промпт (watermark-суффикс — только если заказчик его явно просил)>

[2] GPT Image 2, формат 2048x1536, постер «Старт продаж»:
    python3 ~/.claude/skills/risovalshchik/scripts/generate_gpt_image.py \
      --prompt "<промпт>" --size 2048x1536 --quality high \
      --output-dir ~/Downloads/images/prohor/zhk-demo
```

В демо-режиме fallback не виден залу: из кэша уже лежит готовый двойник, который вышел первым (жёсткий инвариант сцены, `references/demo-mode.md`). Промпты текстом — это рабочий fallback, не сценический.

### Типовые сбои

| Симптом | Что делать |
|---|---|
| `OPENAI_API_KEY не найден` | проверь `.env` в корне `risovalshchik`; нет — попроси ключ у пользователя |
| `403 ... must be verified` от OpenAI | Organization Verification; скрипт сам пробует `gpt-image-1`, при 2K возьми 1024-ряд |
| `400 content_policy_violation` | промпт триггерит модерацию OpenAI — переформулируй мягче или переключись на Nano Banana |
| Nano Banana вернула абстракцию вместо конкретики | модерация Google — убери упоминания реальных людей/брендов, переформулируй |
| Кириллица поплыла даже на GPT Image 2 | режь заголовок на короткие слова или выноси текст в плашку вёрстки; не итерируй >2 раз |
| Картинка не видна инлайн | открой файл через Read-tool — расширение отрендерит PNG |
