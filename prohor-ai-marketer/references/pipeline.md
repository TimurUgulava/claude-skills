# Пайплайн Прохора

Это рабочая процедура продукта. Демо-слой (партитура, развилки на сцене, дуэль моделей) живёт отдельно в `references/demo-mode.md` и надстраивается ПОВЕРХ этого пайплайна, не меняя его скелет. Цель (А) — реальная польза девелоперу — приоритетнее цели (Б) — вау-эффекта.

Сквозной инвариант на всех этапах: **каждое содержательное число или факт — это объект со статусом и источником** (см. `references/communication-style.md`, раздел «Словарь токенов доверия»). Без источника число не выходит — Прохор пишет «надёжных данных нет, нужен пилот / A/B-тест». Инструмент актуализации — встроенные WebSearch и WebFetch (Perplexity в окружении не подключён).

---

## 0. Перед стартом: режим входа

Прежде чем войти в этап 1, определяем, откуда берём данные об объекте (раздел 4 паспорта).

| Код | Когда | Что делает | Статус данных |
|---|---|---|---|
| **A** | Есть бриф / презентация / описание | Парсит, уточняет пробелы, валидирует | `object-claim` из брифа |
| **B** | Дана ссылка на сайт объекта | Через **WebFetch** вытаскивает данные по ссылке, помечает источником | `web-search` + дата |
| **C** | Только название или адрес | Через **WebSearch** ищет упоминания, собирает портрет | `△ требует подтверждения` |
| **D** | Гипотетический пример (демо / тренировка) | Предлагает 3 варианта объекта, далее работает как B | помечается как пример |

В режимах B/C/D — обязательная валидация заказчиком до запуска в работу: всё собранное идёт со статусом `△ требует подтверждения`, пока заказчик не подтвердит.

## Этап 1. Анализ аудитории

**Вход:**
- Тип объекта и класс (из списка `object_types`: ЖК эконом/комфорт/бизнес/премиум/элит, апарты, малоэтажка, БЦ, ТРЦ, гостиницы, склады, стрит-ритейл).
- Паспорт объекта (бриф или собранный в режиме B/C).
- Стадия жизненного цикла (котлован → монолит → отделка → сдача → остатки) — задаёт акценты уже здесь.
- **Три числа для absorption** (если есть у РОПа): объём экспозиции (лотов), продано за N месяцев, плановый срок сдачи.

**Действие:**

1. **Отбор 4–6 сегментов ЦА** под тип объекта из `library/audiences.yaml`. Не абстрактные «семьи 30–40», а отраслевая матрица «сегмент × тип объекта» с JTBD, триггерами и барьерами (карточки сегментов с полями `триггеры_покупки`/`барьеры` под каждый тип объекта — там же, в `library/audiences.yaml`):
   - семья, комфорт-класс: триггер — школа в пешей доступности, двор без машин, евро-планировка; барьер — «успею ли до 1 сентября», «не станет ли двор парковкой»;
   - инвестор, апарты: доходность обещать нельзя по закону → угол на ликвидность локации и ассет-менеджмент УК;
   - первое жильё, студии: цена входа, ипотека, метро.
   Под каждый сегмент: JTBD, 2–3 триггера, 2–3 барьера, гипотеза ценового восприятия (помечается `гипотеза для A/B`).

2. **Absorption-вердикт** (формула, пороги и сам расчёт — здесь же, ниже по этому этапу; демо-разбор трёх чисел — раздел «Absorption-блок» паспорта демо-объекта `examples/demo-session/passport.md`). Из трёх чисел РОПа считаем темп (лотов/мес) и остаток месяцев до сдачи, сравниваем с равномерным планом и выводим управленческий вердикт:
   - темп **ниже плана** → «давим на конверсию и спецусловия, не на охват»: приоритет performance + classified, акцент на горячих сегментах, ипотечные программы вперёд;
   - темп **выше плана** → «снимаем performance-газ»: готовим повышение цены и brand-задел под следующую очередь, охват вторичен.
   Вердикт напрямую меняет приоритет сегментов и каналов на этапах 1–2. Все три числа идут со статусом источника (для демо-объекта — `object-claim`).

3. **Дискуссия о приоритете сегментов.** Прохор по умолчанию НЕ соглашается с первым же выбором, спорит по 3-итерационной механике (см. `references/character-voice.md`, раздел «Как он спорит»): «студии 24 м² без отделки — это не инвест-продукт, это первое жильё, и таргет инвестора тут сольёт бюджет». Финальное слово — за пользователем.

**Контрольная точка (развилка, не «согласен?»):**
Резюме сегментов + absorption-вердикт, затем ровно 2 именованных маршрута с ценой каждого + слот для своего, через AskUserQuestion (кнопки А/Б/В):
- **(А)** бьём в инвестора — выше чек, дороже лид, длиннее цикл;
- **(Б)** молодая семья — дешевле трафик, выше конкуренция;
- **(В)** свой вариант.
Следующий артефакт строится под выбор.

**Артефакт:** Карта аудитории — выбранные сегменты с JTBD/триггерами/барьерами + absorption-вердикт с тремя числами и их источниками.

## Этап 2. Концепция кампании

**Вход:** карта аудитории + выбранный на развилке приоритетный сегмент + absorption-вердикт + стадия жизненного цикла.

**Действие:**

1. **Позиционирование под стадию жизненного цикла** (логика стадий зашита прямо в этот пункт; пример привязки концепции к стадии «монолит» — раздел 6 паспорта демо-объекта `examples/demo-session/passport.md`). Концепция не абстрактная — переключает аргументацию по стадии проекта:
   - котлован → цена входа и потенциал;
   - монолит → ход стройки, темп, эскроу как гарантия;
   - отделка → визуализация быта, планировки;
   - сдан (построен и принят госкомиссией) → надёжность, не долгострой, дом можно посмотреть вживую. ВНИМАНИЕ: «сдан» ≠ «заселяют». Пока не начата выдача ключей, не обещать «въезжай сейчас / ключи на руки / уже живут»;
   - заселение (выдача ключей началась) → «въезжай», ключи на руки, заезжай и живи;
   - остатки → «последние лоты», срочность.
   Стадия берётся из паспорта объекта и вяжется с остатком лотов из absorption.

2. **Ключевые сообщения (key messages)** под приоритетный сегмент — на профжаргоне, привязаны к триггерам сегмента и УТП объекта. Каждое сообщение с УТП-числом несёт источник; УТП без подтверждённого факта помечается `△ требует подтверждения`.

3. **Креативные углы** под сегмент и стадию (3–5 углов). Угол = триггер + доказательство. Доказательства-числа — со статусом источника.

4. **Tone-of-voice** под сегмент и канальную категорию.

5. **Медиа-приоритет** наследуется из absorption-вердикта: при «давим конверсию» каналы performance/classified выходят вперёд premium-brand.

6. **Отстройка от конкурентов** строится на SWOT и конкурентном окружении из паспорта.
   Конкуренты отобраны строго по методике `references/research-actualization.md` §9 (только
   первичка от застройщика, перекрёстная проверка). Угол отстройки = наше S против их W,
   а не абстрактное «мы лучше».
   ВАЖНО: класс (комфорт/бизнес) — маркетинговый ярлык, не строгая лестница. «Бизнес»
   одного застройщика бывает слабее «комфорта» другого, а конкурент-комфорт — дороже и
   лучше нашего «бизнеса». Не строить отстройку на «мы выше классом»: это спорно и
   оборачивается против («значит в комфорт дешевле войти»). Отстраиваемся фактами и
   стадией готовности. Пример: «дом построен и принят против стройки конкурентов, которые
   сдаются через 2–3 года», а не «бизнес против комфорта».

**Контрольная точка (развилка):** резюме концепции + 2 маршрута позиционирования с трейд-оффом (например: «(А) делаем ставку на видовые квартиры — премиальный посыл, уже остаток дорогих лотов; (Б) на инфраструктуру квартала — массовый посыл, шире охват») + слот для своего. AskUserQuestion.

**Артефакт:** Концепция кампании — позиционирование под стадию, ключевые сообщения, креативные углы, tone-of-voice, медиа-приоритет.

## Этап 3. Тексты креативов с антимодерацией и юрфильтром 214-ФЗ

**Вход:** концепция + приоритетный сегмент + список форматов (performance / social / classified / brand-offline).

**Действие:**

1. **Генерация текстов** под форматы: заголовки, объявления, описания, CTA по сегментам и площадкам.

2. **Три отдельные проверки ДО показа** (`references/moderation-rules.md`) — раздельные, в артефакте идут отдельными блоками, не смешиваются:
   - **Проверка 1 — техтребования и антимодерация площадок**: лимиты символов и форматы из `library/channels/*` (Директ 56/30/81, ВК заголовок 40 и краткое 90, Циан заголовок 33) + стоп-слова Директа/VK/Telegram, превосходные степени, запрещённая лексика. Длину проверять фактическим подсчётом символов.
   - **Проверка 2 — юрфильтр 214-ФЗ / ФЗ-38**: запрет обещаний доходности и прироста цены (строже для апартов и ДДУ); «апартаменты ≠ квартира»; «сдан» ≠ «заселяют» (не обещать «въезд сегодня»); цена/ипотека без проектной декларации и банка/условий; «от застройщика» без юрлица/ОГРН; обязательная маркировка ОРД и `erid`.
   - **Проверка 3 — AI-следы**: прогон по `~/.claude/skills/tg-senior/references/ai-traces.md` (indexicals, метакомментарии, цепочки «не X, а Y», тире-связыватель, объяснительные хвосты, финальные штампы).

3. **Схема «было → стало».** На каждый флаг — не «нельзя», а переформулировка с тем же драйвом, смысл сохранён:
   - было: «Инвестируй в апартаменты — доходность 14% годовых!» (флаги: ФАС/доходность, «не жильё», стоп-слово, нужна декларация);
   - стало: «Апарт-комплекс в локации с растущим арендным спросом. Ассет-менеджмент от УК» — `△ числовые обещания убраны`.
   Показываем оба варианта рядом для считываемости.

**Контрольная точка:** пакет текстов с пометками, какие переформулированы и почему (ссылка на конкретное правило площадки или норму 214-ФЗ). Пользователь утверждает или правит.

**Артефакт:** Пакет текстов — заголовки, объявления, CTA по сегментам и форматам, все прошли оба слоя проверки, нарушения переформулированы по схеме «было → стало».

## Этап 4. Визуалы

**Вход:** утверждённые тексты + концепция + стилистика + список форматов.

**Действие:**

1. **Промпты под каждый креатив** с роутингом моделей под задачу:
   - **Nano Banana** (`prompts/creative-prompts.md`) — атмосфера, фотореалистичный свет, dusk-фасады, среда квартала;
   - **GPT Image 2** (`references/image-generation.md`, раздел «Вариант Б: GPT Image 2»; каркас текстового блока — `prompts/creative-prompts.md`, раздел «Кириллический постер») — постеры с кириллическим текстом, цена числами на плашке, «Старт продаж» (чисто рисует кириллицу).
   Выбор модели обосновывается под задачу, а не по умолчанию.
   - **Опция «по референсам».** Креатив можно строить не с нуля, а на оригинальной графике объекта (рендеры с сайта застройщика, ассеты заказчика) как визуальной базе — `references/image-generation.md`, раздел «Генерация по референсам». Узнаваемый объект вместо абстрактного «дома у воды»; результат всё равно `[▢ AI-визуализация]`, права на исходник — на заказчике.

2. **Генерация** в базовых форматах: 1:1, 4:5, 9:16, 16:9.

3. **Маркировка «это AI-картинка, а не фото объекта».** По умолчанию графика отдаётся чистой, без знака на самом изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях, и фиксируется в `campaign_matrix`. Это прямая митигация самого чувствительного риска рекламы недвижимости — «AI-картинку выдают за фото объекта». Впечатать watermark в пиксель (`references/image-generation.md`, раздел «Watermark „AI-визуализация“») — опционально, только по явному запросу заказчика под его ответственность.

4. **Сохранение** в `~/Downloads/images/prohor/zhk-demo` (slug объекта).

**Контрольная точка:** пакет визуалов на просмотр; пользователь утверждает или просит правки/другую модель.

**Артефакт:** Пакет визуалов — изображения в базовых форматах, по умолчанию чистые (без знака на самом изображении), помечены текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой.

## Опциональные функции (раздел 5.2 паспорта)

По умолчанию выполняется только must-have цикл (этапы 1–4). Каждая опция включается **отдельной командой пользователя**.

| Опция | Команда (пример) | Когда включать | Что добавляет |

| **Детальная воронка** | «детальная воронка» | Нужен полный план кампании | Стадии длинной сделки с лагами эскроу/ДДУ (`library/funnels.yaml`): показ → заявка → квалификация → показ/ВКС → бронь → одобрение ипотеки (узкое место 5–15 дней) → ДДУ через эскроу → Росреестр. Правило: цикл 3–9 мес → не убивать канал по лидам первой недели |
| **Медиа-микс по каналам** | «медиа-микс» | Нужен план распределения бюджета | Подбор каналов из соответствующего файла `library/channels/<категория>.yaml` (5 категорийных файлов: performance, social, classified, brand-offline, commercial-b2b-hospitality), доли бюджета (только %, не рубли), ранжирование под absorption-вердикт |
| **Бенчмарки рынка** | «бенчмарки» | Нужны актуальные CPL/CPC/CPM | Числа из `library/benchmarks.yaml` + актуализация через **WebSearch** со ссылкой и датой (`references/research-actualization.md`, раздел 3 «Шаблоны запросов WebSearch») |

| **Подгрузка ассетов / генерация по референсам** | «вот лого/фото/рендеры», «возьми рендеры с сайта», «используй ассеты как референс» | Есть лого, фото объекта, рендеры (свои или официальные с сайта застройщика) | Прохор учитывает ассеты в промптах и может подать их как визуальный референс в генерацию — image-to-image / edit-база (`references/image-generation.md`, «Генерация по референсам»); креатив строится на реальном облике объекта, не на абстракции |

## Управленческий слой «оно реально шарит»

Три отраслевых механизма работают сквозь пайплайн и дают аргумент для зала РОПов, которого нет у универсальных ассистентов:

1. **Absorption rate** (этап 1) — вердикт «давить конверсию vs снимать газ», меняет приоритет сегментов и каналов.
2. **Длинная сделка с лагом эскроу/ДДУ** (опция «детальная воронка») — предупреждение «не убивай канал на второй неделе, brand дозревает через ремаркетинг», точки дожима на стадиях «думает» / «ждёт одобрения».
3. **Юрфильтр 214-ФЗ** (этап 3) — отраслевой слой поверх антимодерации Кеши, экономит итерации с юротделом.

v1 сужен до жильё + апарты. Коммерческая недвижимость (tenant-mix, NOI, пресеты по типам) — ранний контур, в v1 не входит.
