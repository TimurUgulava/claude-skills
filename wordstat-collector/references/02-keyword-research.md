# Сбор семантического ядра + кластеризация

Семантическое ядро = полный список запросов, которые люди реально вводят в Яндексе по теме и которые стоит учесть на странице.

**Источник данных — только Pixel Tools** (один `PIXELTOOLS_API_KEY`):
- `wordstatapikeywords` — расширение ядра через парсинг страниц Wordstat
- `wordstatapi` — проверка частотности конкретных ключей по региону
- `gruppirovka` — кластеризация по подобию топов (опционально)

Никаких внешних LLM-агрегаторов. Только Pixel Tools.

---

## Этап 1. Сбор + обогащение ядра

### Шаг 1.1. Seed-ключи

Seed — исходный набор, от которого расширяем ядро:

1. **Маркер из брифа** (например «ремонт пластиковых окон»).
2. **Близкие формы маркера** — Claude в сессии генерирует 3–5 вариантов: синонимы, морфологические и разговорные формы («ремонт окон пвх», «ремонт стеклопакетов», «починка окон»).

Итог — 3–7 seed-фраз. Claude собирает стартовый `keys.json`, разложив seed'ы по категориям 🔍 SEO-основные (id 4) и 🛒 коммерческие (id 1), у каждого — `query` и `relevance`. Сохрани в `.wordstat-session-*/keys.json`.

Формат стартового `keys.json`:
```json
{
  "4": {"name": "SEO-основные", "emoji": "🔍", "keys": [
    {"query": "ремонт пластиковых окон", "relevance": 1.0}
  ]},
  "1": {"name": "Коммерческие", "emoji": "🛒", "keys": [
    {"query": "ремонт окон пвх москва", "relevance": 0.9}
  ]}
}
```

### Шаг 1.2. Частотность seed'ов через `wordstatapi`

```bash
python scripts/wordstat_enrichment.py \
  .wordstat-session-*/keys.json \
  .wordstat-session-*/input-brief.md \
  .wordstat-session-*/keys_enriched.json \
  --min-freq 10
```

Для каждого seed получаем `overall`, `exact`, `quoted` по региону. Ключи с `overall == 0` — мёртвые, `overall < --min-freq` помечаются `low_freq`.

Seed с явно «не-нашим» интентом (своими руками, отзывы, бесплатно) — **исключаем до расширения**, иначе они затянут всё ядро в чужую сторону.

### Шаг 1.3. Расширение через `wordstatapikeywords`

```bash
python scripts/wordstat_expansion.py \
  .wordstat-session-*/keys_enriched.json \
  .wordstat-session-*/input-brief.md \
  .wordstat-session-*/keys_expanded.json \
  --count-pages 10 --max-new-keys 200
```

Для каждого живого seed:
1. Через `wordstatapikeywords` парсит до 41 страницы Wordstat (связанные запросы).
2. Возвращает фразы **сразу с частотностью** — повторное обогащение для них не нужно.
3. Параллельный режим (лимит 5 задач одновременно).
4. Дедуп фаззи-сравнением (Levenshtein ≥88) — убирает дубли «ремонт пвх окна» vs «ремонт пвх окон».
5. Кап `--max-new-keys` (дефолт 200).

Новые фразы кладутся плоским массивом в `_pending_classification` — без категорий, на классификацию Claude.

**Старт сразу от маркера** (без шагов 1.1–1.2): подать пустой `keys.json` (`{}`) и передать маркер руками:
```bash
python scripts/wordstat_expansion.py empty.json input-brief.md keys_expanded.json \
  --seed "ремонт пластиковых окон" --seed "ремонт окон пвх" --max-new-keys 200
```

### Шаг 1.4. Классификация в 6 категорий (Claude в сессии)

Claude читает `_pending_classification` из `keys_expanded.json`, раскладывает каждый ключ в одну из 6 категорий, проставляет релевантность 0–1 и удаляет `_pending_classification`:

| Эмодзи | id | Категория | Что значит | Пример |
|---|---|---|---|---|
| 🛒 | 1 | Коммерческие | Транзакционный интент (готов покупать) | «ремонт окон цена», «вызов мастера ремонт окон» |
| 📖 | 2 | Информационные | Хочет узнать/изучить | «как починить пластиковое окно» |
| 🎯 | 3 | Long-tail | Длинные фразы (3–5+ слов), низкая частота, высокая конверсия | «замена уплотнителя на пластиковом окне срочно» |
| 🔍 | 4 | SEO-основные | Главные коммерческие запросы — в title, H1, основной H2 | «ремонт пластиковых окон» |
| 🧠 | 5 | LSI / семантические | Тематические слова, которые должны встречаться в тексте | «фурнитура», «уплотнитель», «створка» |
| 🔬 | 6 | Верхнего уровня | Широкие, верхушка воронки | «пластиковые окна» |

**Релевантность 0–1** — насколько ключ подходит конкретному бизнесу. «ремонт окон своими руками» — 0.1 (не наш клиент). «Замена фурнитуры мастер выезд» — 0.95 (идеальный клиент).

Можно дописать полю ключа `recommendation` — короткую подсказку, куда его поставить.

### Шаг 1.5. Контрольная точка после этапа 1

Покажи пользователю (пример):

> Собрал ядро — 198 живых запросов из 247 кандидатов. Остальные 49 — фантомы, Wordstat их не подтвердил.
>
> - 🔍 «ремонт пластиковых окон» — 15 000 показов/мес. Главный коммерческий запрос.
> - 🛒 «замена фурнитуры на окнах» — 2 500. Транзакционный.
> - 🎯 «замена уплотнителя пвх окна срочно» — 50. Низкочастотник, но горячий.
> - 🧠 LSI: «фурнитура», «уплотнитель», «створка», «замерщик».
>
> Запросы про «своими руками», «бесплатно», «отзывы» отфильтровал — другой интент.
>
> **Глянь полную таблицу. Ничего лишнего? Нет ли важной услуги, которую я пропустил?**

После подтверждения — кластеризация (если нужна) и выгрузка в xlsx.

## Кластеризация (опционально)

```bash
python scripts/clustering.py \
  .wordstat-session-*/keys_expanded.json \
  .wordstat-session-*/input-brief.md \
  .wordstat-session-*/clusters.json \
  --method 3 --degree 3 --min-overall 10
```

Через `gruppirovka` группирует ключи по подобию топ-10 Яндекса: если у двух запросов в выдаче совпадает достаточно URL — один кластер. Значит, Яндекс считает их одной темой и ждёт одной страницы.

**Методы**: 0 = soft (2+ общих URL), 1 = middle (3+), 2 = hard (4+), 3 = pixeltools (комбинация подобия топов + лексической близости, **дефолт**). `--degree` 1–10 — строгость общности (дефолт 3).

На вход — только живые ключи (`overall ≥ --min-overall`). На выходе — `clusters.json`: для каждого кластера размер, представительный (самый частотный) запрос, суммарная частотность.

## Промежуточные файлы

В `.wordstat-session-YYYY-MM-DD/`:
- `input-brief.md` — маркер + регион
- `keys.json` — стартовые seed'ы
- `keys_enriched.json` — после обогащения частотностью
- `keys_expanded.json` — после расширения (с `_pending_classification`, затем — классифицированное ядро)
- `clusters.json` — после кластеризации (опционально)

## Почему обогащение обязательно

Без проверки частотности через `wordstatapi`:
- 80–90% LLM-сгенерированного ядра — фантомы (фразы без реального спроса).

С обогащением фантомы отсекаются, остаётся только подтверждённый Яндексом спрос. **Для русского рынка это критично** — без этого шага ядро принципиально не работает.
